# SPD Lab 4.0 Port Design

## Goal

Port the existing SPD Lab modifications from Shattered Pixel Dungeon v3.3.8 onto the official v4.0.0 codebase while preserving the original `master` branch unchanged.

The working branch is `spdlab-4.0-port`, created directly from upstream v4.0.0 commit `2bb34a4e91d29c8785a9363cad6ddfe5122b1d4f`.

## Migration Strategy

Use v4.0.0 as the source of truth and reapply SPD Lab changes on top of it. Do not merge the old 3.3.8 tree wholesale, because v4.0.0 is 316 upstream commits ahead and modifies many of the same core files.

Three migration categories are used:

1. **Direct carry-over** — files that were added only by SPD Lab and do not exist upstream.
2. **Manual integration** — files modified by both SPD Lab and v4.0.0, where only the Lab-specific behavior is reintroduced into the v4.0 implementation.
3. **Rebuild against 4.0 APIs** — code whose surrounding API or assumptions changed enough that copying the 3.3.8 implementation would be unsafe.

## Build Identity

Keep the separate application identity so SPD Lab can coexist with the official game:

- App name: `녹픽던 실험실`
- Package: `com.solji.spdlab`

Retain v4.0 build-system changes, including the v4.0 Android Gradle Plugin level and SDK configuration. The Lab version string should identify both the upstream base and Lab revision, for example `4.0.0-lab-port1`.

## Functional Requirements

The 4.0 port should preserve the existing Lab functionality that was present on `master`:

- Developer item spawning and upgrade controls
- Enchantment and curse controls
- Summoning tools
- Expanded inventory behavior
- Multiple ring/artifact or miscellaneous-equipment behavior currently implemented by the Lab changes
- Experience potion / transmutation-scroll testing utilities already exposed by the developer tool
- Lab mode / `LabLevel`
- Yandere ally summon and behavior
- Yandere heart, ribbon, aura, sprites, and reaction animations
- Separate SPD Lab app identity and save namespace

No unrelated 4.0 gameplay changes should be reverted.

## Save Compatibility

The first port target is code and feature compatibility, not guaranteed migration of existing 3.3.8 Lab save files.

The 4.0 Lab must use its separate package/save namespace. Existing 3.3.8 Lab saves may be tested later, but automatic compatibility is not a requirement for the initial port because upstream save structures and serialized classes may have changed.

## Integration Order

1. Preserve v4.0 build configuration and restore the Lab app identity.
2. Restore Lab-only source and sprite files.
3. Reintroduce asset and sprite registrations.
4. Reintegrate DeveloperTool and equipment/inventory hooks.
5. Reintegrate LabLevel and mode-selection hooks.
6. Reintegrate Yandere ally behavior and UI/animation hooks.
7. Resolve compile failures caused by 4.0 API changes.
8. Build the Android debug APK.
9. Run smoke tests and fix runtime crashes.

## Verification

A successful port requires all of the following:

- Android project compiles from the v4.0 base.
- Debug APK builds successfully.
- Package remains `com.solji.spdlab`, allowing coexistence with official Shattered Pixel Dungeon.
- Normal game start still works.
- Lab mode starts without crashing.
- DeveloperTool opens and core spawn/modify actions work.
- Modified equipment behavior works without corrupting inventory state.
- Yandere ally can be summoned, moves, attacks, saves/loads, and uses its heart/reaction behavior without crashes.
- 4.0-specific content remains present; the port must not silently restore 3.3.8 versions of shared upstream files.

## Risk Areas

- `items.png` is a binary sprite sheet changed by both upstream and SPD Lab; Lab icons must be transplanted into the 4.0 sheet rather than replacing it with the 3.3.8 sheet.
- `Dungeon`, `Hero`, `Level`, and inventory/equipment classes may have serialization or lifecycle changes in 4.0.
- `DeveloperTool.java` and `YandereAlly.java` are large Lab files and may reference renamed or moved 3.3.8 classes.
- Existing 3.3.8 Lab saves are not assumed safe until explicitly tested.

## Non-Goals

- Do not modify or rewrite the existing `master` branch.
- Do not downgrade any v4.0 engine, content, art, or build-system changes merely to make the port easier.
- Do not guarantee old Lab save compatibility in the first pass.
- Do not refactor unrelated Shattered Pixel Dungeon code.
